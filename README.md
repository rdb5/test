# Ghost — رسائل هاتف-إلى-هاتف عبر Nostr + WebRTC

تطبيق PWA (يعمل كتطبيق هاتف) للمراسلة الفورية، حيث:
- **الرسائل والصور والفيديوهات والملفات تُنقل مباشرة بين الجهازين عبر WebRTC** (DataChannel)، وليس عبر أي سيرفر مراسلة.
- **شبكة Nostr تُستخدم فقط "كجرس باب"** لتبادل إشعارات الاتصال (Ring) وبيانات مصافحة WebRTC (Offer/Answer/ICE) — وكلها مشفّرة بالكامل (NIP-44) ولا تحتوي أبداً على نص الرسالة أو الوسائط.
- **لا توجد قاعدة بيانات مركزية ولا حساب على سيرفر.** هويتك = مفتاح تشفير يولّد على جهازك فقط.
- الرسائل تعيش فقط في متغير JS في الذاكرة، وتُمحى فوراً عند إغلاق المحادثة من أي طرف.

## التشغيل

هذا تطبيق ثابت (static) بالكامل — لا يحتاج سيرفر Backend خاص به، فقط استضافة ملفات عبر HTTPS (مطلوب لكاميرا مسح QR وService Worker):

```bash
# أي سيرفر ثابت يفي بالغرض، مثال سريع للتجربة محلياً:
npx serve .
# ثم افتح الرابط على المتصفح (يفضل عبر HTTPS للاختبار الحقيقي على الهاتف،
# جرب ngrok أو استضافة مجانية مثل Vercel/Netlify/GitHub Pages)
```

ثم افتح الرابط على هاتفين مختلفين (أو جهازين)، واضغط "إضافة للشاشة الرئيسية" لتشغيله كـ PWA.

## نقاط أمانة حقيقية يجب أن تعرفها (بصراحة تامة)

بُني هذا التطبيق بأعلى درجة ممكنة من الخصوصية ضمن حدود منصة الويب، لكن أي ادّعاء بـ"حماية 10000%" أو
"غير قابل للاختراق كلياً" هو تسويق غير دقيق مهما كان التطبيق. إليك الحقائق التقنية:

1. **WebRTC ونقاط NAT**: نستخدم خوادم STUN عامة لاكتشاف مسار مباشر بين الجهازين. في بعض الشبكات
   (NAT متماثل / شبكات شركات مقيّدة) يتعذّر الاتصال المباشر تماماً، ووقتها يحتاج WebRTC خادم **TURN**
   لتمرير الحزم (لا يزال مشفّراً بالكامل DTLS + تشفيرنا الخاص، لكنه ليس "هاتف لهاتف حرفياً" في تلك الحالة).
   أضفنا حقل TURN اختياري في الإعدادات.

2. **مصافحة QR والعمل بدون اتصال متزامن**: طلبت أن يعمل الرمز حتى لو الطرفان غير متصلين بنفس اللحظة.
   هذا يتطلب تقنياً نوعاً من "الحفظ والتمرير" (Store-and-Forward) — استثناء وحيد ومتعمد: حدث المصافحة
   يُنشر بعلامة انتهاء صلاحية (NIP-40) فتحذفه الخوادم تلقائياً خلال 24 ساعة كحد أقصى، ويُحذف فور استلامه
   (NIP-09 delete). محتواه مشفّر بالكامل في كل الأحوال. كل ما عدا ذلك (نداء، إشارات، وداع) فوري وغير مخزَّن إطلاقاً.

3. **الإشعارات الفورية عند إغلاق التطبيق تماماً**: تتطلب متصفحات الويب استخدام Push API المدعوم من
   خدمة الدفع الخاصة بالمتصفح (FCM لأندرويد/كروم، APNs لسفاري/آيفون). هذا طرف ثالث حقيقي — لكننا صممنا
   الحمولة (payload) لتكون فارغة تماماً من أي محتوى محادثة: مجرد "نبضة إيقاظ" عامة، والتطبيق بعدها يتصل
   حياً بالـ Nostr relays ويجلب إشارة الاتصال المشفرة بنفسه. لا نص، لا صورة، لا ملف يمر عبر خدمة الدفع أبداً.

4. **كشف لقطة/تسجيل الشاشة**: **لا توجد API موثوقة على الويب** (لا في iOS Safari ولا Android Chrome)
   لاكتشاف لقطة شاشة فعلياً. طبّقنا "تخمينات" أفضل جهد فقط (فقدان التركيز / اختفاء الصفحة) في ميزة
   الرسائل المؤقتة (Flame)، وهي مفيدة كرادع لتقليل الأثر لكنها **ليست ضماناً تقنياً**. أي تطبيق ويب يدّعي
   خلاف ذلك يبالغ.

5. **التخزين على الجهاز نفسه**: هويتك (المفتاح الخاص) وقائمة جهات اتصالك (الاسم + المفتاح العام فقط،
   بدون أي محتوى محادثة) محفوظة في IndexedDB على جهازك لتتمكن من معاودة التواصل لاحقاً. مسح بيانات
   المتصفح أو حذف التطبيق = فقدان الحساب نهائياً بلا استرجاع، تماماً كمحفظة تشفير ذاتية الحفظ.

6. **الخروج/التصغير = مسح فوري**: حسب طلبك، الانتقال للخلفية (visibilitychange) يعتبر "خروجاً" ويمسح
   المحادثة من الطرفين. أضفنا مهلة سماح 3 ثوانٍ لتفادي مسح غير مقصود بسبب نوافذ نظام التشغيل المؤقتة
   (مثل منتقي الملفات/الكاميرا على بعض متصفحات أندرويد التي قد "تُخفي" الصفحة للحظة).

## البنية

```
ghost-p2p-messenger/
├── index.html          الشاشة الترحيبية (توجيه تلقائي)
├── auth.html           إنشاء الهوية (اسم فقط، توليد مفتاح محلي)
├── contacts.html       قائمة جهات الاتصال (بدون بحث إطلاقاً)
├── chat.html           غرفة المحادثة الحيّة (زر نداء، رسائل، وسائط، Flame)
├── qr-connect.html     إنشاء/مسح رمز اتصال لمرة واحدة
├── settings.html       الاسم، الخوادم، الحظر، الحذف النهائي للحساب
├── manifest.json        PWA
├── css/style.css
└── js/
    ├── store.js            IndexedDB: هوية + جهات اتصال + حظر فقط (لا رسائل أبداً)
    ├── auth.js             توليد مفاتيح secp256k1 محلياً
    ├── nostr-signal.js     "جرس الباب": نداء، مصافحة WebRTC، وداع، حضور
    ├── webrtc-p2p.js        اتصال WebRTC المباشر (النقل الفعلي للمحتوى)
    ├── qr-engine.js         توليد/مسح رمز QR لمرة واحدة
    ├── chat-ephemeral.js    حالة المحادثة الحيّة في الذاكرة فقط + تشفير NIP-44 إضافي
    ├── media-flame.js       منطق الرسائل المؤقتة (Flame) وأفضل-جهد لكشف اللقطات
    └── sw.js                Service Worker: يخدم الواجهة فوراً ويستقبل نبضة الإيقاظ فقط
```

## مكتبات خارجية (تُحمَّل من المتصفح مباشرة، لا يوجد بناء/تجميع مطلوب)

- `nostr-tools` عبر esm.sh — توليد المفاتيح، NIP-44، NIP-19، NIP-40
- `qrcodejs` و `jsQR` عبر cdnjs — توليد ومسح رموز QR

## أفكار للتطوير لاحقاً

- استبدال STUN/TURN العام بخادم TURN خاص بك لموثوقية أعلى في الاتصال.
- إضافة Web Push حقيقي (يتطلب مفاتيح VAPID) لتفعيل النداء حتى مع إغلاق المتصفح تماماً.
- تحويله لتطبيق أصلي (React Native / Capacitor) للحصول على أذونات نظام تشغيل حقيقية (مثل حجب لقطة الشاشة عبر `FLAG_SECURE` على أندرويد) — وهو أمر غير ممكن ضمن متصفح ويب عادي.
